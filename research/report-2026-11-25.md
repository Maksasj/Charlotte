# Report: Karin (`symbolic-core`) so far

25 November 2026. Covers the `symbolic-core` branch from initial literate-vault
bootstrapping through commit `1427f0c`: the architecture, the Vault layout and
notation specifics, the plugin tool registry, what works well, and what is still
fragile. Every count in this report is measured directly from the repository and
live `karin-server` state.

## In short

- Karin is a **purely symbolic, non-neural forward-chaining assistant** built in
  Rust (`karin-core` + `karin-server`, 3,644 lines across 21 files) with a
  Vite/React/TypeScript UI (902 lines across 4 files).
- All conversational behavior, domain knowledge, workflows, and learning rules
  live in **28 literate Markdown files** under `vault/` (**136 facts**, **253
  patterns**, **4 seed episodes**), parsed from fenced ` ```karin ` blocks.
- Adding a small number of general Rust primitives (`!=` inequality guards,
  plugin `WorldTool` registry + `@collect`, and `@induce_from_correction` /
  `@approve_pattern`) unlocked reusable Vault layers: knowledge graphs with
  transitive inheritance, typed relations with inverses, data-driven unit
  conversions, multi-step workflows, and correction-driven rule induction.
- **All 8 unit tests and 11/11 end-to-end self-tests pass** (`~130 ms` total,
  zero warnings under `cargo clippy --all-targets -- -D warnings`).
- **What is still weak:** surface language matching is brittle (fillers,
  plurals, articles, typos), rule induction currently targets `likes` + `is_a`
  bridges rather than arbitrary 2-hop predicates, and state is single-user
  global (`subj="user"`).

## How Karin works now

### One turn

```
user message
  │ 1 PREPARE    increment turn; drop ephemeral Working facts
  │              (keep LongTerm facts and Working `dialogue_*` facts)
  │
  │ 2 MATCH      for each Active pattern, unify `when:` conditions against
  │              user text + current facts; skip already-fired (pattern, bindings)
  │
  │ 3 SCORE      rank matches by trust, literal count, fact count, bonuses
  │
  │ 4 FIRE       apply winner's `then:` actions (+assert, ++assert, -retract,
  │              @tool, => reply); record competing matches & effects in trace
  │
  │   └── repeat steps 2–4 up to MAX_STEPS_PER_TURN (12) until a Reply fires
  ▼
reply (or Impasse) + full StepTrace + persisted state.json & vault/.chats/*.md
```

| Subsystem | Location | Responsibility |
|---|---|---|
| Vault loader & DSL parser | `karin-core/src/vault/` (`mod.rs`, `parser.rs`, `syntax.rs`) | Auto-discovers `vault/core/`, `vault/generated-*`, and `vault/.episodes/`; parses fenced ` ``` ` / ` ```karin ` blocks into typed `Fact`, `Pattern`, and `Episode` values |
| Unifier & normalizer | `karin-core/src/unify.rs` | Normalizes text (lowercase, collapsed spaces, stripped trailing `[?!.,;]`), binds `$var` tokens, evaluates `Text`, `Contains`, `Fact`, `NotFact`, `NotEq` |
| Forward-chaining engine | `karin-core/src/engine/mod.rs` | Runs the 12-step turn loop, conflict scoring, chain recording, `new_chat` (clears chat + working/`dialogue_*` while keeping long-term memory), and `reset_from_vault_dir` |
| Learning & induction | `karin-core/src/engine/learn.rs` | `teach_reply`, `feedback`, `generalize_episodes` (anti-unification), `chunk_last_chain` (chain compilation), `induce_from_correction` (2-hop path search + 3-way active learning) |
| Plugin tools & meta-tools | `karin-core/src/tools/` | `WorldTool` trait + static registry (`calc`, `weather`, `define`, `note_save`, `note_list`, `collect`) and meta-tool metadata (`generalize_episodes`, `chunk_last_chain`, `induce_from_correction`, `approve_pattern`) |
| Persistence | `karin-core/src/store.rs` | Atomic `vault/state.json` snapshots + human-readable Markdown chat transcripts under gitignored `vault/.chats/chat-<ts>.md` |
| HTTP server | `karin-server/src/` | Axum REST API (`/api/chat`, `/api/chat/new`, `/api/teach`, `/api/feedback`, `/api/facts`, `/api/patterns`, `/api/meta/*`, `/api/reset`, `/api/selftest`) |
| Web UI | `software/web/src/` | Chat pane with step traces, competing-rule inspector, teach-on-impasse box, Facts/Patterns/Episodes/Tools tabs, **New Chat** and **Reset** controls |

### The formal model

Everything Karin decides is computed over four typed primitives:

- **Fact:** `rel(k1="v1", k2="v2", ...)` with `Scope::Working` (ephemeral, except `dialogue_*` which persists across turns) or `Scope::LongTerm` (persists across turns and **New Chat**), plus `provenance` and `turn`.
- **Pattern (Rule):** `id`, `name`, `status` (`Active` | `Candidate`), `kind` (`Language` | `Reasoning` | `Reply` | `Composite` | `Induced`), `when: Vec<Condition>`, `then: Vec<Action>`, `trust`, `support`, `provenance`.
- **Episode:** `(input, reply, source, generalized)` used by anti-unification to induce `$x` templates.
- **ChainRecord:** Multi-step `(pattern_ids, bindings)` trace eligible for chunking into a single `Composite` pattern.

### Conflict resolution (scoring)

When multiple active patterns match in a step, `score_pattern` (`engine/mod.rs`) computes:

| Feature | Score contribution |
|---|---|
| Base trust | `trust * 2.0` |
| `Text` condition | `3.0 + 0.6 * literal_word_count` |
| `Fact` condition | `+2.0` each |
| `Contains` condition | `+1.0` each |
| `NotFact` condition | `+0.4` each |
| `NotEq` condition (`$a != $b`) | `0.0` (pure safety guard; fixed in `1427f0c`) |
| `PatternKind::Composite` | `+1.2` |
| Contains `Action::Reply` | `+2.5` |

Ties break by higher `support`, then lexicographic `id`.

## The Vault & literate notation specifics

### Directory layout and auto-discovery

`vault_roots()` in `karin-core/src/vault/mod.rs` loads roots in sorted order:

1. **`vault/core/` (14 hand-crafted modules)**
   - `dialogue/frames.md` — shared `need_slot(goal, slot, prompt)` + cancel handling
   - `dialogue/workflows.md` — generic data-driven `goal_need` multi-step workflows (trip planner, reminders)
   - `language/intents.md` — decouples surface phrasings into canonical `intent(...)` facts
   - `knowledge/graph.md` — `is_a`, transitive `is_a`, `prop` with inheritance & child overrides
   - `knowledge/relations.md` — typed `rel(subj, pred, obj)` + automatic `inverse` lookup
   - `learning/meta.md` — conversational triggers for `generalize_episodes` and `chunk_last_chain`
   - `learning/correction.md` — `"what about $item"` / `"you forgot $item"` → `@induce_from_correction` + `approve`/`yes`/`no`
   - `persona/identity.md` — identity, greetings, help, small talk
   - `persona/memory.md` — user profile (`user_name`, city, workplace) + additive `@collect` likes & topic memory
   - `skills/` — `calculator.md`, `definitions.md`, `notes.md`, `units.md`, `weather.md`
2. **`vault/generated-<model-id>/` (13 auto-loaded packs)**
   - `generated-claude-opus-5.5/` (9 files): `assistant-memory.md`, `formulas.md`, `graph-reasoning.md`, `study-quiz.md`, `workflows-extra.md`, `opus2-collect-personal.md`, `opus2-graph-collect.md`, `opus2-opposites-inverses.md`, `opus2-science-pack.md`
   - `generated-gpt-6.2-sol/` (3 files): `sol-planar-areas.md`, `sol-shopping-list.md`, `sol-storage-units.md`
   - `generated-gemini-4-neon/` (1 file): `memory-recall.md`
3. **`vault/.episodes/` (1 file):** `seed.md` (4 seed episodes).
4. **`vault/.chats/` (gitignored, excluded from loading):** Markdown transcripts written automatically per session.

### Compact Rule DSL (` ```karin `)

Only fenced ` ``` ` and ` ```karin ` blocks are parsed; headings, explanations, and other code fences are ignored. Comments inside fences start with `#`.

**Top-level facts and episodes:**
```karin
is_a(child="Rust", parent="programming language")
unit(name="km", dim="length", factor="1000")
episode: "greet Alice" => "Hello Alice, great to see you!"
```

**Rules:**
```karin
rule learn-user-like-topic
when: "my favorite $topic is $thing"
then:
  -dialogue_topic
  +dialogue_topic(kind="likes", topic=$topic)
  ++rel(subj="user", pred="likes", topic=$topic, obj=$thing)
  => "Got it — I'll remember $thing as a $topic you like."
```

**Conditions (`when:`, comma-separated):**

| Syntax | Variant | Notes |
|---|---|---|
| `"weather in $city"` | `Condition::Text` | Lowercased; trailing `[?!.,;]` stripped; `$var` must be whitespace-delimited; trailing `$var` captures multi-word tails |
| `~ "help"` | `Condition::Contains` | Substring match on normalized input |
| `rel(subj="user", obj=$x)` | `Condition::Fact` | Matches facts newest-first; binds unbound `$vars` |
| `!rel(subj="user", obj=$x)` | `Condition::NotFact` | Succeeds only if no matching fact exists |
| `$a != $b` / `$a != "what"` | `Condition::NotEq` | Case-insensitive inequality check after binding |

**Actions (`then:`, single-line or indented multi-line):**

| Syntax | Variant | Notes |
|---|---|---|
| `+rel(k=$v)` | `Action::Assert(Working)` | Ephemeral for current turn, unless `rel` starts with `dialogue_` |
| `++rel(k=$v)` | `Action::Assert(LongTerm)` | Persists across turns and **New Chat** |
| `-rel` / `-rel(k=$v)` | `Action::Retract` | Removes all matching facts |
| `@tool(k=$v)` | `Action::Tool` | Invokes a registered world tool or meta-tool |
| `=> "Hello $name!"` | `Action::Reply` | Substitutes `$vars`, emits reply, ends turn |

### Critical authoring quirks

1. **Newest-first fact matching (`unify.rs`):** `facts.iter().rev()` means the most recently declared matching fact binds first. In `workflows.md`, `goal_need` facts are therefore declared in reverse order of the desired prompt sequence.
2. **Guard fallback replies:** Because `Action::Reply` adds `+2.5`, fallback replies must include `!fact(...)` guards so they cannot preempt multi-step reasoning or tool calls.
3. **Decouple queries via `intent(...)` before `@collect`:** Text-triggered rules score `~8.0`, while pure 2-fact deduction rules score `~6.2`. Routing queries through step-1 `intent(...)` (`run-likes-topic-collect` scores `~4.6`) guarantees background deduction rules (like `induced-likes-topic-from-isa` or `graph-transitive-isa`) settle *before* `@collect` aggregates facts.
4. **Never attach punctuation to `$vars`:** Unification splits templates on whitespace, so `$city` matches `"Tokyo?"` (trailing punctuation stripped from input), whereas `"$city?"` or `"$city's"` will not bind cleanly.

## Plugin tool architecture

`karin-core/src/tools/mod.rs` defines a clean plugin trait:

```rust
pub trait WorldTool: Sync {
    fn info(&self) -> ToolInfo;
    fn run(&self, args: &BTreeMap<String, String>, facts: &[Fact]) -> ToolOutcome;
}
```

Adding a new world tool requires only creating a module under `tools/`, implementing `WorldTool`, and adding `&my_mod::MyTool` to `registered_tools()`.

- **World tools (6):**
  - `calc` — arithmetic expression evaluator (`tools/math.rs`)
  - `weather` — city weather lookup from Vault facts
  - `define` — term definition lookup from Vault facts
  - `note_save`, `note_list` — persistent note management
  - `collect` — generic fact aggregator (`@collect(rel=..., field=..., tag=..., sep=..., <filters...>)`) emitting deduplicated, insertion-ordered `collected(tag, count, list)` or `collected_empty(tag)`
- **Meta-tools (4, dispatched in `Engine::invoke_tool`):**
  - `generalize_episodes` — anti-unification over untaught/taught episodes
  - `chunk_last_chain` — compiles the last multi-step chain into one `Composite` pattern
  - `induce_from_correction` — 2-hop `likes` + transitive `is_a` bridge finder + 3-way active learning (`proposed_rule`, `missing_isa`, `missing_like`, `unknown_item`, `already_known`)
  - `approve_pattern` — promotes a `Candidate` pattern to `Active` directly from chat

## Supporting tooling & model-assisted vault growth

Karin remains **100% symbolic at runtime**, while external models can optionally propose Vault modules offline (always gated by `karin-core`'s parser + self-tests):

- **`.github/skills/vault-suggest/SKILL.md`** (symlinked to `.claude/skills/vault-suggest`): Read-only skill used to generate and live-verify the 13 modules in `vault/generated-{claude-opus-5.5,gpt-6.2-sol,gemini-4-neon}/`.
- **`scripts/expand_phrasings.py`**: Zero-dependency Python script designed for small local Ollama models (`qwen3.5:4b`, 4k context). Groups multi-branch phrasing families, copies `when:` guards and `then:` actions verbatim so the 4B model only generates natural paraphrases, strictly validates `$var` hygiene, skips already-handled phrasings against live `karin-server`, and auto-rolls back if `/api/selftest` regresses.

## Honest assessment: what works well & what is still wrong

### Strengths
- **Full transparency and zero hallucination:** Every reply has an exact causal trace, competing-match scores, and editable Markdown source.
- **High expressiveness per Rust primitive:** A tiny Rust core (~3.6k lines) supports graphs, inverses, workflows, quizzes, unit/storage conversions, planar geometry, shopping lists, and live rule induction purely through Vault files.
- **Safe learning loop:** Induced and chunked rules land as `Candidate` patterns and require explicit promotion (via UI or `"approve"`).

### Real limitations (observed in live testing)
1. **Brittle surface language matching:** Exact token matching fails on leading fillers (`"So, what drinks do I like?"`), plural/singular differences (`drink` vs `drinks`), articles (`"is a black tea"` required an explicit rule), and typos.
2. **Narrow induction primitive:** `@induce_from_correction` currently searches `likes` + transitive `is_a` paths; it does not yet generalize to arbitrary 2-hop `rel` + `rel` or `rel` + `is_a` paths across all predicates.
3. **Single-user global state:** Personal facts hardcode `subj="user"` / `user_name`, and `karin-server` holds one global `Engine`. Multiple users share memory and active `dialogue_*` frames.
4. **Scoring sensitivity to broad wildcards:** Broad templates like `"$child is a $parent"` can collide with more specific phrasings if scoring weights are careless (fixed for `NotEq` in `1427f0c`, but still requires regression discipline as the vault grows).
5. **No contradiction or temporal model:** Updating facts depends on explicit `-fact` retractions per rule; there is no general conflict detector or history timeline.

### Highest-leverage next primitives
1. **Input-edge normalization / optional local canonicalizer** (handles fillers, articles, plurals, and phrasing drift without exploding rule counts).
2. **General 2-hop rule induction** (extend `@induce_from_correction` from `likes` + `is_a` to any `rel` + `is_a`/`rel` bridge).
3. **Multi-user / session scoping** (`HashMap<UserId, Engine>` for strict isolation, or `current_user(id=$u)` for shared-graph cross-user reasoning).
4. **Regression suite of real conversational transcripts** (from `vault/.chats/` and adversarial phrasings) to catch rule collisions automatically as generated packs grow.
