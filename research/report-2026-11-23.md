# Report: the case-based line so far

23 November 2026. Covers everything on the `cbr` and `cbr-data` branches: what
was discovered, what was built, what was fixed, and what is still wrong.
Details and numbers behind each point are in [`findings.md`](findings.md).

## In short

- A Rust engine with a web interface now answers from a Markdown vault and
  learns from conversations.
- Solution shapes (patterns) can be learned from a few hundred labelled
  conversations. That part works.
- Understanding is the weak point. The engine reads only wordings it already
  holds, and nothing built so far changes that much.
- Plain chats are stored and replayed when a new message looks like an old one.
  With 280,000 remembered replies it answers quickly and often wrongly.

## What we discovered

### About the v5 prototype

- **One pattern serves many domains.** The same unedited pattern answered
  refund, warranty, expense, leave, feature and upgrade requests, and a seventh
  domain after two facts were mined from an article.
- **It learned less than it appeared to.** It learned where a pattern applies
  and how far to trust it. The patterns themselves were three hand-written
  skeletons.
- **It had five defects** that gave wrong answers on ordinary input: facts
  shared between two requests in one message, negation ignored, rules about
  another kind of object competing, alternatives decided outside the pattern,
  and a crash when promoting some candidates.
- **It only understood its own vocabulary.** Five rewordings of requests it
  handled ("return" for refund, "died" for faulty) all failed.

### About learning patterns

From the experiment with a simulated teacher, scored on domains never seen:

| Shape | 20 conversations | 80 conversations, 24 domains |
|---|---|---|
| Rule check | 79% | 99% |
| Multi-step procedure | 100% | 100% |
| User corrections | 73% | 88% |
| Lookup feeding a rule check, shown | 71% | 98% |
| The same combination, never shown | 3% | 6% |

- Shapes are learnable, but not from 20 examples. Variety of domains matters
  more than volume.
- Corrections need a memory of the standing decision that the learner cannot
  invent.
- Shapes learned separately do not combine; the combination has to be shown.

### About the engine

- **Pretraining on 240 simulated conversations:** procedures and lookups
  reached 100% on held-out conversations. Rule checks reached 89% (8 of 9), one
  short of the 90% bar, so that pattern is still a candidate and the agent
  declines rule-check requests.
- **With more data:** all three patterns reach 100% from 320 conversations, and
  10,000 are learned in 0.6 seconds.
- **Learned wordings are partly spurious.** At scale it finds "return" for
  refund, and also "don't" for cancel. Validation cannot tell them apart when
  the held-out text comes from the same source.
- **The five rewordings still fail.** None is understood on the pretrained
  vault. After 10,000 simulated conversations two of five intents are read, and
  one of those is answered wrongly.

### About plain chats

- **A small model does not text like a person without firm limits.** The first
  Qwen chats had a median of 38 words per message, with slang. It took three
  rounds of prompt changes plus hard limits on length to aim it at one or two
  polite sentences. The latest prompt has not been seen running on the real
  model.
- **Replaying replies works only for near-repeats.** After 8 chats, none of 13
  held-out messages found a similar remembered one.
- **Public data raises coverage, not quality:**

  | Set | Replies | Held-out messages finding a similar one |
  |---|---|---|
  | DailyDialog | 49,188 | 75% |
  | Schema-Guided Dialogue | 231,640 | 99%, only 19% from the same topic |

- **Tried by hand after training on both**, six messages gave two good replies,
  three wrong ones and one off-target. "Hi! How are you today?" was answered
  with "I need to return a book."
- **More remembered replies made confident near-misses more likely.** Where the
  agent used to say it did not know, it now usually finds something that shares
  a few words.

### About the process

- **Generating data through sub-agents did not work.** A coordinator agent
  cannot send follow-up messages to its own sub-agents, so live two-sided chats
  were impossible one level down. The workaround, ten coordinators each making
  one call per message, was started without a way to watch or stop it. It was
  cut off at 29 of 100 dialogues and everything from it was deleted.
- **The first research line's lesson held.** Its last result was 1 to 2 correct
  of 300 on a benchmark that mostly asked about things never taught. Here every
  claim was checked on a handful of examples first, and three of those checks
  overturned what was expected: the rule-check experiment, the 80-conversation
  pretraining, and the sub-agent pilot.

Teaching data on hand: 240 simulated conversations, 8 Qwen chats, 100
handwritten dialogues, 13,118 DailyDialog and 22,825 Schema-Guided Dialogue
conversations. All have been taught to the vault: the simulated set as
labelled conversations, the rest as plain chats.

## What we fixed

In the engine, compared with v5:

| Defect | Fix |
|---|---|
| Facts shared between requests in one message | Each request has its own frame |
| Negation ignored ("never dropped") | Longest wording wins, and a negator flips a yes/no fact |
| Rules about another kind of object competing | Rules are chosen by intent and object |
| Alternatives decided outside the pattern | The pattern's rules choose offer and deny |
| No memory of the standing decision | Kept in the frame; a correction that changes nothing is confirmed |
| Vocabulary fixed in code | Intents, slots and phrases are notes in the vault |

Found and fixed while building:

- A crash when a chat note had a curly quote at the start of a line. It stopped
  DailyDialog from being taught.
- Invalid request bodies returned plain text; they now return the documented
  JSON error.
- Editing an item without a body silently emptied it; the body is now required.
- A test that assumed no chats had been taught; it now starts from a clean
  copy of the vault.
- Paths and links after each of four moves of files (software and research
  folders, vault and data to the root, raw and processed data).
- Trust values changed by my own test conversations, twice, were put back
  before committing.

In the chat generator, after seeing real output: messages far too long, then
too short and too informal; all conversations of one topic generated before the
next; no view of progress.

## What is still wrong

Ordered by how much it limits the agent.

1. **Reply matching is crude.** Common words are ignored, so a short message
   can be reduced to one word and matched with full confidence. Nothing checks
   that a reused reply fits the conversation.
2. **Understanding.** New wordings are learned only from labelled turns, only
   for intents that already exist, and ways of saying a number ("half a year")
   are not learned at all.
3. **Rule checks are switched off.** The pattern is one held-out conversation
   short of the bar. More simulated conversations fix it in under a second;
   that has not been done.
4. **Schema-Guided Dialogue is taught in a form that does not suit it.** Its
   replies quote search results from the original dialogue, and its labels,
   which are its real value, are stored but unused.
5. **Everything measured so far is against simulated or replayed data.** There
   is no test set of real conversations and no measure of whether a reply is
   good.
6. **Not carried over from v5:** learned split connectors, conflict detection,
   teaching a reply at a cold start, and mining articles into atoms.

Smaller points: the folder of handwritten dialogues is labelled
`gemini-4-neon` at the user's instruction, while the session reported the
model as Claude Fable 5.2; the vault now carries 30 MB of chat notes in git.
